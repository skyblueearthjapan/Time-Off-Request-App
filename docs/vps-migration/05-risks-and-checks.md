# このアプリ固有の危険と、初日の確かめ

作成: 2026-11-26。罠の番号はスキル `references/07-pitfalls.md`（1〜77。60〜77 は残業の移行で足したもの）。
「C-」は初日（段階 0〜1）に行う確かめ。すべて**読むだけ**で、本番に書かない。本番で疑いを確かめるのは「画面を開いて見る」までにし、書き込みが要る確かめはステージングで行う。

## 3. ステージングのコピーで書き換える Settings（M_SYSTEM_SETTING）

「コピーを作成」の直後、写しの GAS を動かす前に書き換える（罠 71）。書いた後は画面で値を確かめる（Sheets の自動補完で変わることがある）。

| キー | 本番の値（見込み） | ステージングの値 | 理由 |
|---|---|---|---|
| `PDF_FOLDER_ID` | `1MQibR08wWsE_OGurO9RocEEDGgDOwo-w` | 新しい試験用フォルダの ID | PDF・サイン画像を本番に書かない |
| `LEDGER_SSID` | `1B7tnsT4lr80o3pFMBxB2zEhsx2UW2PCL48YTQc9i1eU` | 台帳のコピーの ID（**空にしない**。空だと GAS が新しい台帳を作り行を足す） | 本番の台帳に書かない |
| `MAIL_TO` | 〇〇（【要確認】） | imaizumi@lineworks.co.jp だけ | 承認完了・警告メールを本物の宛先に送らない |
| `SOMU_EMAILS`・`ADMIN_EMAILS`・`ALLOW_ADMIN_PAGE_EMAILS` | 〇〇 | 今のまま（画面の権限の試験に使う） | 写しの GAS のメール送信は `notifyMail.gs` のトリガーが無いので起きない |
| `APP_URL` | GAS の `/exec`（@106 か @104） | 写しの GAS のデプロイの `/exec` | 写しの画面から本番へ移動しない |
| `PORTAL_URL` | ポータル | 今のまま | 読むだけのリンク |
| `MASTER_SOURCE_SSID`・`CALENDAR_SOURCE_SSID` | マスタ元・残業 DB | 今のまま | 読むだけ。写しの GAS の同期は手で動かすときだけ（トリガーはコピーされない） |
| `PDF_TEMPLATE_SSID` | 空の見込み | 今のまま | 使っていない |

ほかに:
- 写しの DB の T_LEAVE_REQUEST の `PDF_URL`・`PDF_FILE_ID`・`サイン画像URL` を空にする（写しの GAS が本番の PDF をゴミ箱へ移さないため。罠 72）。
- 統合業務メールは本番の DB だけを読むので、ステージングの書き込みは通知に出ない（確認済み・定数）。
- 写しの GAS に内部用の入口を入れてデプロイするときは、`VPS_INTERNAL_TOKEN` をステージング用の値で入れる（本番と別の値）。

## 4. 切り替えの当日に足す確かめ（残業の手順書 B 章に足すもの）

- B-1 で、申請中・2 次承認待ちの件数（C-3 と同じクエリ）。
- B-5 移転モードは**両方のデプロイ**に当てたかを `list-deployments --json` で確かめる（R-1、罠 60）。
- B-6 で `syncAllMasters` のトリガーを消す。統合業務メールのトリガーは**消さない**（別のアプリ）。
- B-16 の後、VPS が書いた T_LEAVE_REQUEST の行を、統合業務メールの条件（承認状態の文字・休暇日が Date 型）で読んで件数が同じことを確かめる。
- 翌朝 7:00 の「朝の報告」と 17:00・18:00 の通知の件数を、VPS の画面の件数と比べる（オーナーの受信箱。見守りの初日）。
